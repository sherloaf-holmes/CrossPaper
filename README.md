## What's different in this fork

This fork is designed maintain the full CrossInk experience (and therefore the core Crosspoint firmware) while adding sync for articles saved to Instapaper.

### Instapaper Sync

To use Instapaper Sync, you'll need a personal API key for Instapaper.

Instapaper Sync can be configured by initiating a "File Transfer" via Wi-Fi, and then configuring/Syncing in the "Articles" tab of the web interface. 

#### Instapaper Sync relies on the web interface

Instapaper's API provides full text in an HTML format, and images in their original resolution. To avoid forcing low power eInk devices to process full articles, we instead offload the HTML->ePub conversion & downsampling of images to a more powerful device via javascript in the web interface.

The reader itself holds the credentials, sync status, and sync mechanism, so the user does not need to download any special app.

The existing file transfer web server allows easy offloading of the heavy processing to any connected device.

Instapaper API requests, as well as images from certain sources, are required to pass through the device, but as much as possible we try to offload everything to the web browser.

## Development quick start (from CrossInk)

CrossInk uses PlatformIO for building and flashing firmware. See [Getting Started](./docs/development/getting-started.md) for prerequisites, clone setup, and validation commands.

### Nix/NixOS

Nix/NixOS users can enter the development shell with either `nix develop` (flakes) or `nix-shell`:

```bash
nix develop -f nix
# or
nix-shell nix
```

To flash a connected ESP32-C3 device, enable PlatformIO's udev rules in your NixOS configuration:

```nix
services.udev.packages = with pkgs; [ platformio-core.udev ];
```

After rebuilding the system configuration, reconnect the device or reload udev rules.

### Build / flash / monitor

Connect your device to your computer via a USB cable. Before the first build, initialize the repository's submodules (including `freeink-sdk`):

```sh
git submodule update --init --recursive
```

Then flash the firmware using the correct environment for the device. The `default` environment is for the X3/X4 devices. ESP32-S3 devices have their own named environments.

```sh
pio run -e default --target upload
```

If PlatformIO reports `PackageException: Can not create a symbolic link for freeink-sdk/libs/hardware/BatteryMonitor, not a directory`, the `freeink-sdk` submodule is not initialized. Run the submodule command above and retry.

See [Testing and Debugging](./docs/development/testing-debugging.md) for serial logging, simulator checks, static analysis, and bug-report guidance.
